fix: 协议三处根本性错误 + 提权漏洞；门禁改为向运行中的主机取证

由真实主机逐项探测发现（不是读文档推断）。此前 App 的协议层三处全错，
导致整条 /api 桥在真机上完全不可用，而 50 项进程内断言全绿：

1. endpoint 用**斜杠**分隔，不是点号。
   权威依据（app.asar 内 dsh-api-gateway）：
     function endpointOf(namespace, method) { return `${namespace}/${method}`; }
   实测：session/list → 200 被认领；session.list → 404 "not found"。
2. payload 必须包成 { args: { … } }，不是裸对象。
   裸 {} 被拒：Remote payload must contain exactly one plain-object args field
3. args 的键名是**服务端声明的形参名**（含前导下划线），不是业务字段名。
   实测：session/list 要 { _request: {} }；其余要 { request: {...} }。
   取法：故意传错参数，主机回 missing "request"，比读源码权威。

另修：host.describe **在真实主机上不存在**（枚举 41 个 endpoint 里没有它），
App 的握手与 ping 改用 session/list。

## 顺带发现并修复一个提权漏洞

特权闸门用点号名单（settings.describe），而真实请求走斜杠 endpoint
（settings/describe）—— 比对不上，直接放行。实测 settings.describe
**成功返回了配置内容**。已加 normalizeMethod() 归一化，并覆盖首尾斜杠、
大小写变体（18 项单元验证全符合）。

## 门禁的根本缺陷也修了

check-app-methods.mjs 早期从 app.asar 静态扫描字符串，因此**漏掉了
「斜杠 vs 点号」这个致命差异** —— 静态扫描只能证明「这个名字出现过」，
证明不了「这个 endpoint 被认领」。现在改为向**运行中的主机**发真实探测请求
（未认领的 endpoint 固定回 404 "not found"），这是唯一可靠判据。
主机不可达时明确报无法验证并非零退出。

同时把「App 依赖特权方法」也算作失败（此前只警告不失败）。

## 实测结果

session/list → 59 个真实会话，标题正确、running 状态正确
session/page → 94 条记录，8 种真实事件类型
  (assistant/message, tool/call, tool/result, step/start, step/end,
   workspace/changes, turn/end, session/end-seed)
特权闸门 → settings/describe、credentials/set、host/pickDirectory 全部拦在主机之前
协议端到端 8/8；网关 E2E 50/50；方法名门禁通过；契约审计通过
突变验证：注入 session.history 红、依赖特权方法红
