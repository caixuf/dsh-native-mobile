## 一、必须先知道的协议事实（全部经真实主机探测确认）

这些是我花了多轮探测才拿到的，**别再重复踩**。

### 1.1 调用信封（两个层次，都要对）

网关 `POST /mobile-gateway/api/<method>`，请求体：

```json
{
  "type": "client-request",
  "rpcId": "<随机字符串>",
  "method": "<method>",
  "payload": { "args": { ... } }
}
```

⚠️ **`payload.args` 外层键名 = 服务端形参名**，且**因方法而异**：

| 方法 | 形参名 |
|---|---|
| `session/list` | `_request` ← **带下划线，唯一一个特例** |
| `session/page` / `session/create` / `session/prompt` | `request` |
| `workspace/create` / `workspace/rename` | `request` |
| `workspace/follow` | **不接受任何 args**（见 1.3） |

**怎么自己探出正确形参名**：故意传错，主机自己会报：

```
args fields do not match the descriptor: missing "request"; unexpected "cwd"
```

这比读源码权威 —— 反映的是**当前运行实例**的真实 descriptor。

### 1.2 `workspace/list` 不存在

```
POST /mobile-gateway/api/workspace/list  →  HTTP 404  not found
```

**DSH 宿主根本没有这个方法。** 所以：

> **工作区分组必须从 `session/list` 的 `cwd` 字段聚合出来。**

实测数据（115 条会话）：

```

  35  C:\Users\20247\Downloads\aiwork
  14  C:\Users\20247\.dsh\profiles\desktop\node_modules\dsh-bot-gateway\runtime-data\users\telegram-8192862144
   7  C:\Users\20247\Downloads\aiwork\dsh-native-mobile
   7  \\wsl.localhost\Ubuntu\home\caixuf\code\FlowEngine
   6  \\wsl.localhost\Ubuntu\home\caixuf\code\claude-code-providers
   6  \\wsl.localhost\Ubuntu\home\caixuf\code\chongqing-job-decision
   1  C:\Users\20247\Documents\deepseek-harness\default-workspace
```

→ **8 个工作区**。注意含 **WSL 路径**（`\\wsl.localhost\Ubuntu\...`），显示时要友好化。

### 1.3 `workspace/follow` 是 stream 方法

```
ERROR[gateway/signature-invalid]
  workspace/follow: stream Remote methods must be opened through the stream carrier
```

它**不能走普通 RPC**，必须经 WebSocket 流式通道（`/api/remote.mux` 的 `open` 帧）。

**建议：不要依赖它。** 工作区状态从 `session/list` 聚合完全够用。

### 1.4 `workspace/create` 可用，但要 `request.path`

```json
{ "request": { "path": "C:\\Users\\20247\\Downloads\\aiwork" } }
```

成功返回：

```json
{ "workspace": { "workspaceId": "...", "path": "...", "title": "aiwork", "sessionIds": [...] },
  "created": false }
```

其他键名（`cwd` / `name` / `title` / `root` / `directory`）**全部报 `input-invalid`**。
`created=false` 表示该路径已有工作区（幂等）。

### 1.5 `session/list` 的真实字段

```json
{
  "sessionId": "session-...",
  "updatedAt": 1791950966841,
  "agentAvailable": true,
  "running": true,
  "blank": false,
  "cwd": "C:\\Users\\20247\\Downloads\\aiwork\\dsh-native-mobile",
  "projections": { "kind": "sequenced", "values": { "title": "...", "sessionListMetadata": {...} } }
}
```

- **工作区靠 `cwd`**（顶层字段，不在 projections 里）
- `title` 在 `projections.values.title`
- 网关已对 `session/list` 做**响应瘦身**（剥掉 tokenUsage/contextBreakdown），别以为拿到了全量

### 1.6 子代理会话判据

**只认 `origin == "subagent"`**，不能退化成 `parentSessionId != null`。

实测：有 1 条带 `parentSessionId` 但没有 `origin` 的，是 `session.fork` 出来的**普通会话**，用裸 sessionId 打开**正常返回**。按 parent 判会误伤。

## 二、环境与工具（本机特有的坑）

### 2.1 构建

```powershell
# 一条命令出 APK：前端构建 → 拷 dist/ 进 WebView 壳 → Gradle 打包 → 收产物
npm run build:apk        # = tsc -b && vite build && node scripts/build-apk.mjs
# 产物：dist-apk\dsh-mobile-v0.4.0.apk
```

- Android 侧现在只有 `android/` 这个 WebView 壳（源码仅
  `android/app/src/main/java/io/github/dshmobile/app/MainActivity.kt`）；
  旧的 `apps\android` Kotlin 实现与它的 111 条单测已在 `c3c0bf9` 删除
- **PATH 上没有 java**：`scripts/build-apk.mjs` 里写死了 `JAVA_HOME` 与 `gradle.bat`
  的绝对路径（`C:\Users\20247\Downloads\android-toolchain\...`），换机器要改这两个常量
- `android/` 下**没有** `gradlew.bat`（wrapper 随 `apps\android` 一起被删），
  别写 `.\gradlew.bat`；现存测试是 Web 侧的 `npm run test`
  （`scripts/test-markdown.mjs` 44 条 + `scripts/test-incremental.mjs` 10 条）
- 本机 PATH 上没有 `npm`/`pnpm`（见 2.2）时，把 `build:apk` 展开手动跑：
  `tsc -b && vite build && node scripts\build-apk.mjs`
  —— `build-apk.mjs` 只负责拷 `dist/` + 打 Gradle 包，**要求 `dist/` 已存在**
- 首次跑慢（下依赖），用长超时或后台跑

### 2.2 PowerShell 5.1 的坑（踩过多次）

- 无 `pwsh`；无 PATH 上的 `npm`/`pnpm`
- **`.ps1` 必须存成带 BOM 的 UTF-8**，否则中文吞引号 → ParseError
  - ⚠️ **edit 工具会剥掉 BOM**，改完要补回：
    `[IO.File]::WriteAllText($p,$t,[Text.UTF8Encoding]::new($true))`
- 手改文本用 write 工具，**不要用 `Set-Content`**（写 ANSI）

## 七、一条经验

**遇到"做不到"时，先确认是能力缺失还是自我设限。**

这次两个典型：
- 「运行中不能输入」→ 协议早支持，**是我们 UI 写死了 `enabled = !running`**
- 「工作区列表拿不到」→ 确实没有 `workspace/list`，**但 `cwd` 聚合就够了**

先探测（`list-endpoints.mjs` + 故意传错参数）再下结论，比读文档可靠 —— DSH 的客户端 bundle 和文档都不可信，**只有真实主机的响应是权威**。
